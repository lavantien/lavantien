# languages strip generator

Pipeline behind the profile README. Every constant lives in `scripts/config.py`.

## flow

1. `scripts/github_client.py` lists repos through the `gh` CLI with the GraphQL field set pinned in `GH_JSON_FIELDS`, reading `GH_TOKEN` from the environment.
2. `scripts/aggregate.py` keeps public, non-fork, non-archived repos, sums language bytes, and builds table rows as `PINNED_REPOS` in config order at their fixed years (a pinned repo missing from aggregation, e.g. the archived modern-swe-library, falls back to a live `gh repo view` snapshot of stars, forks, description, createdAt, and top languages; the live description wins verbatim even when empty and the config description is only the failure fallback when the fetch itself returns nothing; the no-AI cutoff resolves from the batch reference repo or `NO_AI_FALLBACK_CUTOFF`; per-entry `no_ai` and `langs` overrides take precedence, and modern-swe-library pins `langs` to the 1296 raw markdown lines of its single readme.md, counted 2026-10-19 as 136322 bytes of LF text with trailing newline, blank lines included, because linguist classifies that file as documentation and reports no language at all), then free-market repos sorted by stars descending with an alphabetical tie-break, skipping `EXCLUDED_REPO_NAMES` (the profile repo and neovim), filled up to `TABLE_REPO_LIMIT = 20` entries. Every row also carries its top `TABLE_LANGS_N` languages via `item_top_langs`, counted under `TABLE_LANGS_ALLOW` (the strip's `PROG_LANGS` plus Shell, PowerShell, and Markdown, so script-heavy repos like dotfiles and dev still get their row; Markdown stays inert in batch data since linguist excludes documentation markdown, it only reaches the table through the pinned entry) with the same byte sums and sort the strip uses. Star and fork counts and descriptions sync live every run: batch rows read them from the same live `gh repo list` (`forkCount` rides `GH_JSON_FIELDS`), snapshot rows from `gh repo view`.
3. `top_languages` filters the sums to `PROG_LANGS`, sorts by bytes descending with an alphabetical tie-break, and cuts at `TOP_N`.
4. `scripts/svg_strip.py` renders one icon plus a `Name Size` label per language into a self-contained SVG at natural width. Icons load from `assets/devicons/<slug>-<variant>.svg`; a missing file or unmapped language falls back to a gray letter tile.
5. `scripts/readme_writer.py` rewrites the marker regions of `README.md` and writes `assets/languages.svg`. Each repo cell carries a meta row of `(year)`, the star count with `STAR_GLYPH` (✪), and the live fork count with `FORK_GLYPH` (♆), each bold except the year, separated by `META_ITEM_JOIN` (four non-breaking spaces, so the gap renders four spaces wide and the meta line never wraps), with the optional no-AI badge as the last item. Below it sits the language chip row: one standalone recolored icon (`assets/lang-icons/<slug>-<variant>.svg`, produced by `scripts/lang_icons.py` through the same `load_icon` recolor the strip uses) plus the strip's `format_bytes` count (`format_bytes` truncates to hundreds precision, 1296 renders 1.2K, exact multiples drop the decimal, and the display never overstates the count), `META_JOIN`-glued so a chip never wraps, and `LANG_CHIP_JOIN` (three `&nbsp;` plus a plain space, a four-space gap that still breaks there) between chips so long pairs wrap instead of stretching the equal columns. The language name lives only in the img alt, so the repo columns stay narrow for the description lanes; a language without a vendored icon keeps the `Name Size` text form so its chip stays legible.
6. `make icons` re-vendors icons, `make generate` rebuilds from the recorded fixture, `make update` goes live (both ensure every referenced lang-icons file exists first), `make record` refreshes the fixture with public repos only.

## icon sources

Icons come from two pinned upstreams, resolved per slug through `ICON_SOURCES` and `ICON_SOURCE_OVERRIDES`.

- `devicons/devicon` @ `7330accdbc47e2dc0c19789a48533c4a3c50fe58`, fetched 2026-10-05 via `gh api repos/devicons/devicon/commits/master --jq .sha`.
- `simple-icons/simple-icons` @ `ac1bf3df4e3d4cd1ce03cedb96d6165d2e98fe99`, fetched 2026-10-09 the same way. Devicon ships no typst icon, checked at the pinned ref and at master, so the Typst mark comes from simple-icons.

Variant and stand-in caveats, all verified against the `icons/` tree of devicon at the pinned ref: Rust and C ship no plain variant, only original and line, so they use original. Blade has no devicon and rides the Laravel mark. Hack has no devicon and rides the PHP mark. The Markdown mark is `markdown-original.svg` from devicon at the pinned ref, fetched 2026-10-19, an outline icon whose paths carry no fill attribute at all, which the recolor treats like black and paints the linguist blue `#083fa1`. Lua brand navy `#000080`, Rust brand black, and any default black fill vanish on the GitHub dark theme, so `RECOLOR_FILLS` replaces them with the language brand hex at embed time.

Color sources: shields.io ported hexes for the original workflow set, MathWorks orange for MATLAB per linguist, gray for Hack per linguist, Typst teal `#239dad` per `lib/linguist/languages.yml` in `github-linguist/linguist`. Markdown deviates from linguist navy `#083fa1` on purpose: that fill fails the 3:1 contrast minimum on the GitHub dark canvas (2.01:1) on a thin outline mark, so the chip uses GitHub's Primer accent blue `#2f81f7` (5.05:1 on dark, 3.75:1 on light), the same visible-on-both-themes rule that drove the shields port for the original set.

## invariants under test

- `PROG_LANGS`, `LANG_COLORS`, and `DEVICON_MAP` share one key set, so every allowlisted language has a color and an icon entry.
- Every mapped slug resolves to a configured icon source and its `icon_path` template formats into an `icons/` path.
- The golden SVG pins the exact rendered bytes of the sample top 10, which transitively pins the vendored icon files themselves.
- Pinned repos render live data while public and non-archived. A pinned repo absent from aggregation (archived, private, or forked) falls back to a live `gh repo view` snapshot of stars, forks, description, and createdAt; the live description wins verbatim, the config description is only the failure fallback, and the `no_ai` and `langs` entry overrides take precedence, so it keeps its badge and language row instead of silently degrading. The cutoff resolves from the batch reference repo with `NO_AI_FALLBACK_CUTOFF` as the fixed fallback.
- modern-swe-library renders its star count as `200+<live count>` via `stars_prefix`.
- Every repo created strictly before the creation timestamp of `NO_AI_REFERENCE_REPO` (llm-tournament) shows the `assets/no-ai.svg` badge after its fork count, derived at aggregation time from the same batch or from `NO_AI_FALLBACK_CUTOFF` when the reference repo is absent, and the reference repo itself is never badged.
- The table spans the full width (`TABLE_WIDTH`) with four equal `TABLE_CELL_WIDTH` columns, so both name lanes and both description lanes share identical widths. `META_ITEM_JOIN` glues year, star count, fork count, and badge into one unbreakable line, so the meta row never wraps under the link at desktop profile width; every join is U+00A0, which carries no line-break opportunity, so on narrow viewports only GitHub's own table CSS (`width: max-content`, horizontal scroll, or a forced CSS break) can move the line, never the line breaker. Names and descriptions are HTML-escaped at render time, and marker-less adoption only claims tables whose opening tag is the bare legacy `<table>` or the generator's exact `<table width="...">`, so attributed foreign tables survive a fresh adoption. The badge svg holds a single logo cut from the original artwork: red ring (`NO_AI_BORDER_COLOR`), green AI letters (`NO_AI_TEXT_COLOR`).
- Language chips reuse the strip's `format_bytes` sizes and `load_icon` recolor, so a black or navy brand fill that would vanish on the GitHub dark theme (Rust, Lua, Typst) is written brand-colored into `assets/lang-icons/` and referenced from the README; a language with no vendored icon degrades to a text-only chip rather than a dangling img. Two languages sharing one vendored mark (Hack and PHP ride the php icon) get language-suffixed files so their colors never collapse onto one overwritten image, and the daily workflow commits `assets/lang-icons` alongside the README and strip so a newly referenced icon never dangles on the profile. `prune_icons` deletes standalone icon files the current table no longer references, so the directory holds exactly the referenced set and the workflow's `git add` commits the deletions too.
- The updated line is fully config-driven, `UPDATED_PREFIX` + a `UPDATED_TIME_FORMAT` stamp taken in the fixed `UPDATED_TZ_OFFSET_HOURS` zone (UTC-5, label derived from the offset so the two cannot drift) + `UPDATED_SUFFIX`, and `_UPDATED_LINE_RE` derives from `re.escape(UPDATED_PREFIX)` so writer and format cannot drift.
- `make mutate` swaps token-level mutants into `scripts/` against the suite and requires a clean `scripts/` tree so restores stay verifiable.
- Two expressions avoid comparison operators because the equality boundary they would need is unreachable, which leaves any `<=`/`<` form with a structurally equivalent mutant: `tag.rpartition("}")[-1]` for namespace stripping and `m.end() in range(updated.start())` for the owned-table bound in `readme_writer`.
